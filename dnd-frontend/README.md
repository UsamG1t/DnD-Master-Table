# DnD Frontend — «Стол мастера»

SPA на Svelte 5 + Vite. Работает поверх FastAPI-backend из первой части проекта.

## Запуск

```bash
npm install
npm run dev            # http://localhost:5173, backend должен работать на :8000
```

Dev-сервер проксирует `/auth`, `/dnd`, `/characters`, `/games` (включая WebSocket) на `http://127.0.0.1:8000` — см. `vite.config.js`; другой адрес backend задаётся переменной `BACKEND_URL`. Для продакшен-сборки (`npm run build`) задайте `VITE_API_BASE=https://ваш-сервер` в `.env.production` — тогда фронтенд ходит на backend напрямую (CORS уже открыт).

## ВАЖНО: backend-patch

В каталоге `backend-patch/` лежат две обновлённые копии файлов backend. Скопируйте их поверх существующих:

```bash
cp backend-patch/dnd_data.py   ../dnd-backend/app/routers/dnd_data.py
cp backend-patch/games.py      ../dnd-backend/app/routers/games.py
cp backend-patch/dnd_client.py ../dnd-backend/app/services/dnd_client.py
```

Что добавлено (v5), файлы патча: `dnd_client.py`, `dnd_data.py` (→ `app/routers/`, `app/services/`), `games.py`, `models.py`, `main.py` (→ соответствующие места), **новый** `rfc.py` → `app/routers/rfc.py`.

**Цепочка данных DnD** (каждый запрос): community_dnd_file_cache (принятые RFC-объекты) → dnd_file_cache (статический кеш из explore_2024.py) → кеш БД → HTTP `/api/2024` → HTTP `/api/2014` (species/subspecies маппятся в races/subraces) → при недоступности сети устаревший кеш БД. Настройки: `DND_API_PREFIXES`, `DND_FILE_CACHE_DIR`, `DND_COMMUNITY_CACHE_DIR`, `DND_FILE_CACHE_URL_BASE`.

**DnD RFC**: пользовательские объекты любых категорий; администратор сервера — константа `SERVER_ADMIN = "UsamG1t"` в `app/routers/rfc.py` (также любой is_admin). Принятые объекты пишутся в community-кеш под тем же sha256-хешем и появляются в списках `/dnd/{category}` с меткой community.

Установка кеша: `cp -r out/cache dnd-backend/dnd_file_cache`. После копирования файлов перезапустите uvicorn — таблица community_objects создастся автоматически.

## Структура

```
src/
  main.js                    точка входа (Svelte 5 mount)
  App.svelte                 навигация + переключение страниц
  app.css                    дизайн-токены: тёмное «сукно стола», бумажные листы, золото
  lib/
    api.js                   fetch-обёртка: JWT, ошибки, ws-адрес
    auth.svelte.js           реактивное состояние аутентификации (руны)
    router.svelte.js         hash-роутер (#/characters/12, #/games/3)
    dnd.js                   кеш справочников + правила доступности по уровню + подписи
    ops.js                   генерация операций {op_id, path, value, ts} диффом
  components/
    Modal.svelte             модальное окно
    InfoButton.svelte        кнопка info: сжатое описание + ссылка на источник
    DataTree.svelte          рекурсивный рендер структуры персонажа
    GameMessage.svelte       сообщение комнаты: chat / dice / sheet / log / system
  pages/
    Auth.svelte              вход и регистрация
    Characters.svelte        панель персонажей: «В игре» со ссылкой, видимость в логе
    Editor.svelte            редактор: зависимые списки, заклинания, серые недоступные
    Games.svelte             создание игры / вход по логину-паролю
    GameRoom.svelte          комната: чат по WebSocket, кубики, персонажи, лист в чат
```

## Как реализованы требования

**Зависимые списки.** Выбор расы подтягивает `raw`-ответ расы и показывает список подрас; выбор класса — подклассы, а если у класса есть `spellcasting`, появляется секция «Заклинания» только с заклинаниями этого класса. Смена класса очищает выбранные заклинания.

**Недоступное по уровню.** Правила в `lib/dnd.js`: черты — с 4 уровня, подклассы — с 3-го, круг заклинания ≤ ⌈уровень/2⌉. Выбрать можно всё, но в итоговой панели такие элементы получают класс `.locked` — бледно-серые, `pointer-events: none`, кнопка info отключена, рядом бейдж с причиной.

**Кнопка info.** У каждой расы, класса, заклинания, умения, черты, предмета из базы. Показывает сжатое описание из `/dnd/{category}/{index}` (внутри нет ссылок), внизу — «Полное описание в базе данных →» по `source_url`.

**Сохранение.** Создание — `POST /characters` с полной структурой. Редактирование — дифф старой и новой структуры по путям из `ops.js` → пачка операций `{op_id, path, value, ts}` в `PATCH`. Это ровно формат офлайн-журнала будущего Android-клиента, так что серверная логика (LWW, трансляция в лог игры) одна на всех.

**Игровая комната.** История — `GET /messages`, живые события — WebSocket `/games/{id}/ws?token=...`. Системные события (персонаж вошёл/вышел) заставляют перезагрузить списки участников и персонажей. Игрок без персонажа видит список своих свободных персонажей и выставляет одного. Мастер видит логин-пароль игры, добавляет своих персонажей и при отправке листа в чат отмечает скрываемые пути; игрокам чекбоксы скрытия не показываются вовсе.

## Известные ограничения

Переименование персонажа после создания пока не поддержано (имя — колонка, а не часть `data`; операции журнала его не трогают) — потребует маленького эндпоинта на backend. Списки категорий и raw-ответы кешируются в памяти вкладки на всё время сессии — для SRD это нормально. Правила доступности упрощены под SRD (полукастеры вроде паладина получают круги медленнее, чем ⌈уровень/2⌉).
